# Уведомления в Telegram — дизайн

Дата: 2026-08-02. Проект: pockterm.

## Задача

Узнавать с телефона, что агент в tmux-сессии (Claude Code, Qwen, Codex —
любой TUI) просит ответ или закончил работу, когда pockterm закрыт.

Два триггера:

- **вопрос** — на экране появилось интерактивное меню;
- **готово** — экран не менялся 30 секунд после того, как что-то делал.

## Решения

| Вопрос | Решение |
|---|---|
| Канал | Telegram Bot API, `sendMessage`. Работает при закрытой PWA, без VAPID и подписок, одинаково на Android и iOS |
| Охват | Сессии, к которым подключались через pockterm. Сессия попадает под наблюдение при первом attach и остаётся, пока жива |
| Шум | Молчим, пока сессию смотрят: есть подключённый клиент **и** его вкладка видима |
| Порог тишины | 30 секунд, настраивается `POCKTERM_IDLE` |
| Ответ из Telegram | Вне объёма. Приём апдейтов Bot API означает запись в терминал из внешнего сервиса — отдельная поверхность атаки, отдельное решение |

## Архитектура

Детектор меню сейчас живёт в браузере (`web/js/detect.js`), а уведомление
нужно ровно тогда, когда браузера нет. Значит детекция переезжает на
сервер, к тому же экрану её приводит `tmux capture-pane`.

```
tmux ──capture-pane──▶ watch.Watcher ──Event──▶ telegram.Client ──▶ Bot API
                            ▲
                      viewers (кто смотрит)
                            ▲
                     server.go (WS: attach, visible)
```

Новые пакеты:

- `internal/detect` — порт `detect.js` на Go. Та же эвристика: подряд
  идущие строки 1,2,3… с маркером выбора или рамкой.
- `internal/watch` — цикл опроса, состояние сессий, правила событий,
  реестр зрителей.
- `internal/telegram` — транспорт: POST `sendMessage`, ничего больше.

Правится:

- `internal/tmuxcmd` — argv для `capture-pane`.
- `internal/proto` — control-фрейм `visible` от клиента.
- `internal/server` — регистрация сессии под наблюдение при attach,
  учёт зрителей, снятие при закрытии сокета.
- `internal/config` — `POCKTERM_TG_TOKEN`, `POCKTERM_TG_CHAT`,
  `POCKTERM_TG_LINK`, `POCKTERM_IDLE`, `POCKTERM_TG_PREVIEW`,
  `POCKTERM_TG_API` (корень Bot API — локальный bot-server или заглушка,
  через неё же прогоняется живая проверка).
- `web/js/app.js` — шлёт `visible` при `visibilitychange` и на connect.

## Один детектор, два языка

Логика дублируется в JS (кнопки в UI) и Go (уведомления). Расхождение
между ними — вопрос времени, поэтому обе реализации гоняются на общем
наборе случаев: `test/fixtures/menus.json`. Тест на любой стороне,
который разошёлся с фикстурами, красный.

## Правила событий

Состояние на сессию: хэш экрана, время последнего изменения, был ли
вообще ввод-вывод, отправлено ли «готово», подпись последнего меню.

- Экран изменился → обновить время, снять флаг «готово».
- Меню появилось или сменилось → событие **вопрос** (один раз на меню).
- Тишина ≥ `POCKTERM_IDLE`, при этом активность была, «готово» ещё не
  слали → событие **готово** (один раз до следующей активности).
- Сессия исчезла (`capture-pane` не отвечает) → снять с наблюдения.

Событие, пришедшее на сессию, которую смотрят, гасится, но состояние
обновляется — задним числом такое уведомление не приходит.

«Готово» не шлётся до первой активности после начала наблюдения: иначе
любая давно простаивающая сессия уведомляла бы сразу после attach.

## Формат сообщения

```
❓ claude просит ответ
Do you want to make this edit to app.js?
1. Yes
2. Yes, allow all edits this session
3. No, and tell Claude what to do

https://cc.hitromudr.ru
```

```
✅ claude закончил
> make check прошёл, 14 тестов зелёные

https://cc.hitromudr.ru
```

Ссылка — из `POCKTERM_TG_LINK`, без токена: токен в облачном чате не
нужен, установленная PWA его уже знает.

## Безопасность

Содержимое экрана уходит во внешний сервис. Это осознанный размен, и он
ограничен: превью обрезается (меню — не более 8 пунктов, «готово» — одна
последняя непустая строка, каждая строка не длиннее 200 символов).
`POCKTERM_TG_PREVIEW=off` оставляет только факт события и имя сессии.
Раздел «Модель безопасности» в README дополняется предупреждением.

Уведомления выключены, пока не задан `POCKTERM_TG_TOKEN`.

## Ошибки

- Telegram недоступен или вернул не-200 — записать в лог и продолжить.
  Уведомления не ретраятся: устаревшее «просит ответ» хуже пропущенного.
- `capture-pane` вернул ошибку — сессия снимается с наблюдения.
- Опрос tmux не должен мешать вводу-выводу: вотчер живёт в своей
  горутине, с терминалом не разделяет ничего.

## Тестирование

- `internal/detect` — общие фикстуры.
- `internal/watch` — инъекция `Capture`, `Notify`, `Now`: время
  контролируемое, tmux не нужен. Случаи: вопрос один раз на меню,
  «готово» один раз, тишина без активности молчит, зритель гасит.
- `internal/telegram` — `httptest`, проверка пути и тела запроса.
- `internal/server` — фрейм `visible` меняет видимость зрителя.
- Интеграция — реальный tmux плюс фейковый Bot API на `httptest`:
  вывод в pane → тишина → сообщение «готово».
