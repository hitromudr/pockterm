## Упрощение ввода и байтовый стенд (закоммичено, не выкачено)

1. **`web/js/app.js` — упрощение модели ввода.** Было четыре хозяина одного
   `textarea`: xterm с IME, перехват `beforeinput` на удалении, отправка
   содержимого поля (`flushComposition`) и синтетический `compositionend`.
   Каждая их комбинация давала свой дефект: слово возвращалось, пробел после
   удаления пропадал, удаление «вставляло строку». Всё это снято; остался один
   вызов `commitInput()` перед `⏎`/`Alt⏎` — без него сообщение уходит без
   последнего слова, и это факт про Gboard, а не выбор.
   Страница поднята до **v59**. **Не выкатывалось**: установка — только
   `workflow_dispatch`.
2. **`test/ui/bytes.test.mjs` — 4 из 4 зелёные**, весь набор `make test-ui` —
   22 из 22 за 20 секунд вместо 79. Идея прежняя: сессия поднимается в
   `raw`-режиме (`stty raw -echo; exec cat -v`), экран становится расшифровкой
   байтов, пришедших в pty.
3. **`test/ui/stand.mjs`** — параметр `raw`, свой свободный порт на каждый
   стенд (`PT_UI_PORT` по-прежнему пиннит его для отладки одного файла) и
   выключенная строка статуса tmux в `raw`-режиме.

### Почему он был красным — ни одна из вчерашних гипотез

- **Первая и главная причина в самой странице.** Упрощение ввода унесло
  `keepsTerminalFocus()` вместе с соседним обработчиком `beforeinput`, оставив
  три вызова. Страница падала на загрузке (`ReferenceError`) — список сессий не
  успевал появиться, и все браузерные тесты ждали элемент, которого не будет.
  Диагноз дала не логика, а `serverLog()` стенда: `client: {"event":"error",…}`
  в журнале — тот же канал, что и на телефоне.
- **Стенд отдаёт вшитые в бинарь ассеты.** Правка `web/` без `make build`
  ничего не меняет; `make test-ui` пересобирает сам, `node --test` — нет.
- **Порт всё-таки участвовал, но только при параллельном прогоне.** Оба файла
  брали `8139`, второй сервер не поднимался, и его страница показывала чужой
  список. Остаточных процессов не было.
- **Строка статуса tmux — часть текста экрана** и переписывает себя часами,
  поэтому «экран как растущая расшифровка» не работал ни в одну сторону.
- **Перерисовка после перезагрузки страницы не мгновенная**, и чтение экрана
  посреди неё приписывало хвост прошлого теста началу следующего.

## Чего просил владелец и что не сделано

- **Инерция прокрутки.** Сейчас свайп переводится в колёсико по строке —
  плавнее, чем было, но без инерции после отпускания пальца. Просьба: «не
  юиксово».
- **Уведомление должно открывать ту сессию, в которой работа закончилась.**
  Сейчас тап по уведомлению открывает приложение и последнюю сессию. Нужно:
  `notify()` в мосте принимает имя сессии, `PendingIntent` несёт его,
  `MainActivity` открывает `cc.hitromudr.ru/?session=<имя>`, страница при
  наличии параметра подключается именно к ней. Требует правки Kotlin и подъёма
  `versionCode` (иначе обновление не предложится).
- **Цифры `1 2 3`** убраны по просьбе владельца (место занял `Alt⏎`). Если
  вернутся нумерованные меню — вернуть в «⋯».
- **`⇧Tab`** убран, а Claude Code переключает им режим разрешений. Место есть.

## Грабли, на которые уже наступали

- **WebView, а не Chrome.** Нет асинхронного clipboard API, Notification API,
  выбора файла и установки PWA; devtools не открыть. Всё это идёт через мост
  `PockNative`. Признак в диагностике: `wv` в UA, `standalone: false`,
  `native: true`.
- **Диагностика — главный инструмент.** `journalctl -u pockterm | grep client:`
  показывает окружение, путь буфера обмена, загрузки, ошибки страницы,
  состояние клавиатуры при переключении. Три диагноза за ночь пришли оттуда, а
  не из рассуждений.
- **Стенд не воспроизводит телефон.** В десктопном chromium нет IME, экранной
  клавиатуры и того поведения WebView, из-за которого фокус поднимает
  клавиатуру. Правки этих слоёв подтверждает только устройство.
- **Фокус ≠ открытая клавиатура.** Жест «назад» прячет клавиатуру, оставляя
  фокус. Признак «клавиатура открыта» считается от максимальной высоты
  видимой области в этой ориентации — сравнение с `innerHeight` бессмысленно,
  страница просит `interactive-widget=resizes-content`.
- **Push ничего не устанавливает.** Установка — только `workflow_dispatch`
  (Actions → deploy → Run workflow, или API `dispatches`). Причина: установка
  перезапускает юнит, а в нём сидит тот, кто правит.
- **Версию поднимать в двух местах** — `web/sw.js` (`VERSION`) и
  `web/js/app.js` (`APP_VERSION`), иначе «⋯» показывает прошлую.
- **Половина дефектов этой ночи — регрессы от предыдущей правки того же
  вечера.** Порядок, который себя оправдал: узкое изменение → `make test-ui` →
  выкатка → подтверждение с телефона → следующее.
