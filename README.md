# pockterm

[English version](README.en.md)

Карманный терминал: мобильная PWA, подключённая к tmux-сессии, которую
раздаёт один Go-бинарник. Сделан, чтобы управлять
[Claude Code](https://claude.com/claude-code) (или любым TUI) с телефона.

- **Один бинарник.** Статика PWA встроена; на хосте нужен только `tmux`.
- **Настоящий терминал.** xterm.js поверх моста WebSocket→PTY, плюс
  панель клавиш (Esc, Tab, стрелки, залипающий Ctrl) для мобильных
  клавиатур.
- **Grouped-сессии tmux.** У каждого клиента свой размер экрана: телефон
  не сжимает окно tmux на ноутбуке.
- **Переживает перезагрузки.** Если целевой сессии нет, pockterm
  поднимает её настраиваемой командой.

## Быстрый старт

```bash
make build
POCKTERM_SESSION=claude ./bin/pockterm
# открыть http://127.0.0.1:8130
```

## Конфигурация (окружение)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `POCKTERM_LISTEN` | `127.0.0.1:8130` | Адрес прослушивания. Не-loopback требует `POCKTERM_TOKEN`. |
| `POCKTERM_SESSION` | `claude` | tmux-сессия (группа), к которой подключаемся. |
| `POCKTERM_BOOTSTRAP` | login shell | Команда создания сессии, если её нет. |
| `POCKTERM_TOKEN` | пусто | Общий токен (`?token=...`); обязателен вне loopback. |

## Развёртывание

Сам pockterm слушает loopback. TLS и аутентификацию (клиентские
сертификаты или встроенный токен) обеспечивает обратный прокси перед
ним. Пример systemd-юнита — `deploy/pockterm.service.example`.
Прокси обязан пропускать WebSocket-upgrade для `/ws` и отключать
буферизацию. Прокси также обязан сохранять заголовок Host в исходном виде
(nginx: `proxy_set_header Host $host;`) — сервер сверяет `Origin` с `Host`
запроса и отклоняет апгрейд, если прокси его переписывает.

## Модель безопасности

pockterm отдаёт полный терминал любому, кто подключился. Относитесь к
нему как к SSH: не выставляйте наружу без TLS и аутентификации.
Бинарник отказывается слушать не-loopback адрес без токена.
