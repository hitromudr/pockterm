# pockterm

[English version](README.en.md)

Карманный терминал: мобильная PWA-окно к твоим tmux-сессиям, которое
раздаёт один Go-бинарник. Удобно управлять с телефона любой консолью —
например [Claude Code](https://claude.com/claude-code) или любым TUI.

- **Один бинарник.** Статика PWA встроена; на хосте нужен только `tmux`.
- **Настоящий терминал.** xterm.js поверх моста WebSocket→PTY, плюс
  панель клавиш (Esc, Tab, стрелки, залипающий Ctrl) для мобильных
  клавиатур. Ctrl читает следующую букву с обычной клавиатуры — в том
  числе русскую, по позиции клавиши (`Ctrl` `к` — это `^R`, как в
  терминале на ноутбуке), и завершает композицию сам, иначе буква
  осталась бы у клавиатуры. Панель `^A ^E ^K …` открывается тогда,
  когда клавиатуры на экране нет.
- **История под пальцем.** Свайп прокручивает историю tmux, `⇞`/`⇟` листают
  по экрану, а полоса справа показывает, где в выводе ты находишься, и
  перетаскиванием переносит куда угодно. Полоса рисуется поверх терминала:
  в потоке она сузила бы панель, tmux перерисовал бы её под новую ширину,
  и страница читала бы экран, переформатированный собственным скроллбаром.
- **Список и подключение.** pockterm показывает запущенные tmux-сессии
  и присоединяется к выбранной. Он **не создаёт** сессий сам — ты
  запускаешь их на сервере как обычно.
- **Grouped-сессии tmux.** У каждого клиента свой размер экрана: телефон
  не сжимает окно tmux на ноутбуке. Размер страница называет в адресе
  сокета — клиент подключается сразу с ним, а не с 80×24 «пока не сказали»:
  окно у группы одно, и такой клиент перерисовывал бы его под всеми
  остальными.
- **Кнопки ответа.** Интерактивное меню (например, запрос разрешения
  Claude Code) распознаётся по маркеру выбора и рамке, а не по любой
  нумерации, поэтому нумерованный список в тексте кнопок не создаёт.
  Пока экран прокручен в историю (copy-mode), кнопки скрыты.
  Строка `Type something.` — не вариант ответа, а поле ввода самого меню:
  её кнопка нарисована контуром, подводит указатель к полю и отдаёт
  клавиатуру, ничего не нажимая. Enter над пустым полем агент получает
  как отказ отвечать — это и был отчёт «кнопка отправляет отмену».
  Вопрос, принимающий несколько ответов, кнопками не отвечают, а отмечают:
  на них стоит ☐/☑, и Enter по варианту переключает галочку. Заканчивает
  такой вопрос отдельная зелёная кнопка `⏎ Submit` — страница подводит к
  ней указатель по одному шагу и нажимает Enter только на том экране, где
  видит указатель на самой строке.
- **Обмен с буфером.** Кнопка ✂ включает режим выделения: свайп
  перестаёт прокручивать, текст выделяется системно, кнопки Copy и
  Paste переносят его в буфер устройства и обратно в терминал. Долгий тап
  берёт абзац целиком и помечает его на месте — долгий тап на другом
  абзаце добавляет его к выделенному, повторный по помеченному снимает
  метку, а короткий тап по тексту не делает ничего; Copy отдаёт помеченное
  в том порядке, в каком оно на экране.
  В буфер уходит только то, что лежит внутри замороженной копии — и уходит
  разметкой, а не картинкой: то, что агент написал как `**слово**`, на панели
  осталось жирным начертанием, а в буфер вернётся звёздочками (у панели
  спрашиваются атрибуты, `capture-pane -e`; жирное — это `**`, цвет строчного
  кода — обратные кавычки). Таблицы из рамок собираются обратно в
  Маркдаун-таблицу: `┌┬┐ │ ├┼┤ └┴┘` — это `| столбец | столбец |`, перенесённая
  ячейка склеивается, первый ряд становится заголовком. Выравнивание читается из
  отступов в ячейках — единственного, что от `:---:` и `---:` остаётся на
  панели, — и только по строкам данных: шапку агент центрирует всегда.
- **Картинка из буфера.** Скриншот вставляется тем же Paste (или Ctrl+V,
  или перетаскиванием файла): в pty пролезают только нажатия клавиш,
  поэтому картинка уходит на сервер, ложится файлом рядом с кэшем
  пользователя, а в терминал печатается путь к ней — то, что агент и так
  умеет читать. Скриншотов можно выбрать сразу несколько (📎, до десяти):
  они уходят по одному, а пути печатаются одной вставкой, то есть агент
  получает одно сообщение про несколько файлов, а не сообщение на каждый.
- **Сессии из интерфейса.** `+` создаёт по готовому пресету (`shell`,
  `claude`, `yolo`, `continue`), `✎` переименовывает, `✕` закрывает в два
  касания. Команду страница не передаёт — только имя пресета; запускает всё
  тот же Makefile, которым пользуются руками. Нужно потому, что с телефона,
  где не осталось ни одной сессии, создать её было нечем.
- **Уведомления в Telegram.** Сервер сам смотрит на экран сессии через
  `capture-pane` и пишет в чат, когда агент просит ответ или затих. Это
  работает при закрытом pockterm — то есть тогда, когда и нужно.

## Быстрый старт

```bash
make build
./bin/pockterm
# запусти сессию: tmux new-session -d -s work
# открой http://127.0.0.1:8130 и выбери её
```

## С телефона за три минуты

Полный путь наружу — домен, TLS, сертификаты — нужен постоянной установке.
Чтобы просто посмотреть, как это работает, хватит своей же сети:

```bash
sudo POCKTERM_LISTEN=0.0.0.0:8130 bash deploy/install.sh
```

Установщик поставит сервис, сгенерирует токен и напечатает QR-код с адресом
этой машины — наведите камеру телефона, подключённого к тому же Wi-Fi.

Трафик при этом идёт по HTTP: внутрь пускает токен, но никто не мешает
соседу по сети читать содержимое. Для постоянной работы поставьте впереди
обратный прокси (см. ниже) — тогда QR печатает уже настоящий адрес:

```bash
POCKTERM_PUBLIC_URL=https://pockterm.example.com sudo -E pockterm qr
```

## Установка на сервер

```bash
git clone https://github.com/hitromudr/pockterm && cd pockterm
sudo bash deploy/install.sh        # или: make install
```

Go нужен не всегда: без тулчейна установщик берёт опубликованную сборку для
этой архитектуры (linux amd64 и arm64) и сверяет её с `SHA256SUMS` релиза.
Скачать принудительно, даже когда Go есть, — `POCKTERM_FROM_RELEASE=1`;
взять сборку из другого места — `POCKTERM_RELEASE_BASE=<url>`. Файл, не
совпавший с суммой, не ставится.

Скрипт собирает бинарь, кладёт его в `/usr/local/bin`, генерирует токен в
`/etc/pockterm/pockterm.env` (права 600), пишет systemd-юнит и запускает
сервис от того пользователя, чьи tmux-сессии нужно обслуживать — под `sudo`
это тот, кто его вызвал. Повторный запуск ничего не ломает: токен
сохраняется, юнит перезаписывается только при изменении. Удалить —
`sudo bash deploy/install.sh --uninstall`.

Он же делает то, что раньше оставалось человеку после установки, — иначе
первая сессия на новом телефоне требовала прочитать этот файл до конца:

- **Проверяет, что на хосте есть `tmux`**, и отказывается ставить сервис без
  него, печатая команду установки для найденного пакетного менеджера. Пустой
  список сессий на телефоне выглядит как сломанный терминал, а не как
  отсутствующий пакет. Отсутствие `make` — предупреждение: без него не
  работает только кнопка «+».
- **Кладёт Makefile сессий** (`deploy/sessions.mk.example`) в корень
  проектов и прописывает туда `POCKTERM_SESSION_DIR`, так что «+» работает
  сразу. Корень по умолчанию — домашний каталог обслуживаемого пользователя;
  другой задаётся той же переменной: `sudo POCKTERM_SESSION_DIR=/home/me/projects
  bash deploy/install.sh`. Чужой Makefile не перезаписывается и не берётся в
  дело: `make claude` в нём — неизвестная цель, а не сессия, поэтому
  установщик оставляет и файл, и переменную, и говорит, что делать. Свою
  копию он узнаёт по слову `pockterm-sessions` в шапке и не трогает правки.
  Выключить — `POCKTERM_NO_SESSIONS=1`.
- **Перезапускает сервис, если env-файл изменился** — и только тогда:
  перезапуск рвёт открытые терминалы, а установка, ничего не изменившая, не
  должна стоить никому переподключения.
- **`--tg` настраивает уведомления в Telegram по ходу установки**: спросит
  токен бота, найдёт chat id, пошлёт пробное сообщение и перезапустит сервис.
  Отдельно это `pockterm tg-setup --write /etc/pockterm/pockterm.env`, и
  забывался там как раз перезапуск.

Сервис слушает loopback. Чтобы попасть на него снаружи, поставьте впереди
обратный прокси — готовые примеры лежат рядом:

| Файл | Когда |
|---|---|
| `deploy/nginx-token.conf.example` | TLS плюс встроенный токен. Быстро начать |
| `deploy/nginx-mtls.conf.example` | Клиентские сертификаты. Держать долго |

Если впереди mTLS, токен не нужен и только мешает: сервер начнёт отвечать
`401` на ссылку без него, а выглядит это в браузере как машина без сессий.
Ставьте с `POCKTERM_NO_TOKEN=1`:

```bash
sudo POCKTERM_NO_TOKEN=1 bash deploy/install.sh
```

Уже выданный токен установщик при этом не трогает — только предупреждает.

Токен в адресной строке попадает в историю браузера и в логи прокси, поэтому
для постоянной установки предпочтительнее mTLS: там сканер интернета видит
отказ в рукопожатии, а не страницу входа. Инструкция по выпуску сертификатов
и установке их на телефон — в шапке `nginx-mtls.conf.example`.

## Подключение телефона

```bash
make qr PUBLIC_URL=https://pockterm.example.com
```

QR-код печатается прямо в терминал: наведите камеру — откроется адрес вместе
с токеном. **Страница сама предложит установку** — полоса под шапкой списка
сессий, кнопка «Установить»: на Android Chrome собирает и ставит настоящий
пакет, приложение появляется в списке приложений и запускается своим окном без
вкладок. В Safari события установки не существует, поэтому там та же полоса
показывает путь: «Поделиться» → «На экран „Домой“».

Раньше предложение было только кнопкой в настройках ящика, двумя тапами
глубже, — и первый заход закрывал вкладку, ничего не установив. Кнопка там
осталась: ею ставят после того, как полосу закрыли (она больше не появляется —
«позже» помнится).

Ту же ссылку можно получить без QR — `pockterm qr https://...` печатает и
код, и сам адрес.

## Конфигурация (окружение)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `POCKTERM_LISTEN` | `127.0.0.1:8130` | Адрес прослушивания. Не-loopback требует `POCKTERM_TOKEN`. |
| `POCKTERM_TOKEN` | пусто | Общий токен (`?token=...`); обязателен вне loopback. |
| `POCKTERM_TG_TOKEN` | пусто | Токен бота от @BotFather. Пусто — уведомлений нет. |
| `POCKTERM_TG_CHAT` | пусто | ID чата. Задаётся вместе с токеном, иначе старт откажет. |
| `POCKTERM_TG_LINK` | пусто | Ссылка, которую бот дописывает к сообщению (без токена). |
| `POCKTERM_TG_PREVIEW` | вкл | `off` — слать только факт и имя сессии, без текста с экрана. |
| `POCKTERM_TG_API` | `https://api.telegram.org` | Корень Bot API: локальный bot-server или тестовая заглушка. |
| `POCKTERM_IDLE` | `30s` | Сколько тишины считать завершением работы. |
| `POCKTERM_NOTIFY_FILE` | файл в конфиге пользователя | Где помнить переключатель уведомлений; `off` — держать в памяти (теряется при перезапуске). |
| `POCKTERM_PRESETS_FILE` | файл в конфиге пользователя | Где помнить свои кнопки сессий; `off` — держать в памяти. |
| `POCKTERM_UPLOAD_DIR` | кэш пользователя | Куда сохранять вставленные картинки; `off` — выключить загрузку. |
| `POCKTERM_SESSION_DIR` | рабочий каталог сервиса | Где лежит Makefile с целями сессий (кнопка «+»); `off` — не давать создавать. |

## Создание сессий с телефона (кнопка «+»)

Команду страница не передаёт — только имя пресета (`shell`, `claude`,
`yolo`, `continue`), и сервер запускает `make -C <каталог> <пресет>`. Что
такое сессия, решает этот Makefile, а не pockterm: он же и остаётся
единственным местом, которое знает про песочницу, нумерацию и slice.

Готовый образец — `deploy/sessions.mk.example`, и **устанавливает его сам
`deploy/install.sh`**: в корень проектов, вместе с `POCKTERM_SESSION_DIR` в
env-файле. Руками это нужно только там, где корень выбран другой и установщик
уже прошёл:

```bash
cp deploy/sessions.mk.example ~/work/Makefile   # поправьте CLAUDE внутри
echo 'POCKTERM_SESSION_DIR=/home/youruser/work' | sudo tee -a /etc/pockterm/pockterm.env
sudo systemctl restart pockterm
```

Без `POCKTERM_SESSION_DIR` сервер ищет Makefile в своём рабочем каталоге —
для юнита это то, что сказано в `WorkingDirectory=` (в примере юнита и в том,
что пишет установщик, это домашний каталог пользователя). Makefile не найден
— кнопка «+» просто выключается, о чём сказано в журнале при старте.

### Папки проектов: где начать сессию

Кнопка «📁» в ящике сессий показывает второй список — папки корня проектов
(того же `POCKTERM_SESSION_DIR`) и сам корень первой строкой. Тап по папке
открывает те же четыре пресета, и сессия начинается **в ней**, а имя берёт
**от папки**: `natal`, второй раз `natal-2`. Имя выбирает Makefile — ему
передаются `DIR=` и `PREFIX=`, а номер, свободный и как имя сессии, и как имя
группы, по-прежнему его дело.

Почему это не «кнопка +, только с путём»: сессия почти всегда про проект, а на
телефоне нет `cd`, который стоило бы набирать. И `claude-1`, `claude-2`,
`claude-3` — не список, по которому можно ориентироваться; папка в имени
отвечает на вопрос «что это», а команда — нет. Переименование осталось: имя от
папки — начальное значение, а не запрет.

Список — один уровень вложенности, без скрытых каталогов. Страница присылает
только имя папки, сервер сам склеивает путь и отказывает всему, что не одно
простое имя внутри корня (`..`, `/`, точка в начале): значение попадает в
командную строку.

Старый «+» ничего не потерял — он по-прежнему запускает пресет в корне.

### Кнопки сессий: четыре умолчания и свои, одним списком

Внизу ящика есть блок **«Настройки»**, а в нём — кнопки сессий: название и
команда. Своя кнопка встаёт рядом с четырьмя умолчаниями под «+» (и в меню над
терминалом — это один список), запускается в той же папке и с тем же именем от
папки. Так `qwen`, `opencode` и что угодно ещё появляется с телефона, а не через
правку Makefile на хосте.

**Четыре умолчания — такие же записи этого списка**, поэтому у них та же правка и
то же удаление. Умолчание отличается тем, что его id — цель Makefile (`shell`,
`claude`, `yolo`, `continue`), а команда пуста: что делает цель, решает Makefile.
Задайте умолчанию команду — и оно пойдёт через ту же цель `custom`, сохранив свой
id, а значит и знак на табах, которые оно уже открыло: `claude --model opus`
остаётся `✦`. Удалённую кнопку сервер запускать отказывается — иначе удаление
было бы просто скрытием.

**Кнопка может называть цель Makefile, а не нести команду.** Напишите в поле
команды `make cont-yolo` — и это будет именно та цель, как `make claude` у
умолчаний (строки списка так и показывают, что кнопка запускает). Нужно потому, что
в Makefile есть цели, которых нет среди четырёх, а `make cont-yolo` как **команда**
запускает make внутри сессии, которую кнопка только что создала: рядом появляется
вторая, а первая умирает. Имя цели — ворота уже́ и надёжнее команды: буквы, цифры и
дефисы, без аргументов и без пути. Цель — из **вашего** Makefile, доверие то же,
что у четырёх; неизвестную make отклонит своим сообщением, и оно приедет в ящик.

**«↻ Сбросить к умолчанию»** возвращает четыре и не трогает ваши: четыре — это
умолчание, а `qwen`, набранный на телефоне, — нет. Два касания, как у любого
удаления здесь, потому что сброс отменяет переименования и команды.

Что запускает — по-прежнему Makefile: команда уезжает в `CMD=` одной цели
`custom`, которая оборачивает её тем же пусковым механизмом, что и остальные
цели. Makefile без этой цели ответит своим «no rule to make target», и текст
приедет в ящик как есть.

Команда проверяется до того, как попадёт на командную строку: буквы, цифры,
пробелы и `- _ . / = : , @ +`, начало — буква, цифра или путь. Кавычки, `$`,
`;`, `&`, `|` отклоняются с объяснением: значение доходит до шелла внутри
рецепта, и это ворота, а не совет.

**Знак кнопки выбирается из сетки.** Слева от подписи — кнопка со знаком; тап
открывает сетку глифов **прямо под ней**, тап по глифу выбирает его и закрывает
сетку, тап по уже выбранному — снимает. Кнопка показывает не выбранный знак, а тот,
которым кнопка будет нарисована: пока ничего не выбрано, это и есть ответ страницы,
и он следует за названием по мере набора. Глифы, у которых есть цветной вариант,
несут его (`❄️`, а не `❄`) — в текстовом виде знак принимает цвет названия и на
вкладке становится незаметным. Знак рисуется в меню «+», на вкладках, которые эта кнопка
открыла, и в ящике. Раньше знак можно было получить только эмодзи в начале
подписи — приём, о котором надо было знать, и минус символ от имени, которого и
так 24; поэтому три своих кнопки рисовались одинаковой `★`.

Если знак не выбран, порядок такой: эмодзи в начале подписи (как раньше), затем
то, чем известен id — свой глиф у умолчания или имя знакомого агента, — и общая
`★`, когда сказать нечего. Знакомых имён ровно два: **Claude — холод (`❄`),
Codex — солнце (`☀`)`; третий был бы гаданием, а любой из этих перебивается одним
тапом в сетке.

У каждой кнопки в списке два действия: `✎` — изменить, `✕` — убрать **в два
касания**, как у сессий: первое краснит крестик и спрашивает, второе удаляет,
и через четыре секунды взвод сам спадает. Одно касание тут было ровно до того,
как случайный тычок унёс кнопку, ничего не спросив: строки в ящике выглядят
одинаково, и жест — то, чем им различаться нельзя. Правка
берёт название и команду в те же два поля (второй пары полей на телефоне нет,
как нет и второго поля для переименования сессии), помечает строку, о которой
они, и «Добавить» становится «Сохранить»; повторный тап по `✎` отменяет.
Изменение — не «удалить и завести заново»: кнопка сохраняет свой id, а
именно им помечены табы сессий, которые она открыла, — набрав ту же команду
заново, вы получили бы сессии с меткой кнопки, которой больше нет.

Список живёт на хосте (`POCKTERM_PRESETS_FILE`, рядом с переключателем
уведомлений), а не в браузере: запускается всё на хосте, второй телефон должен
видеть те же кнопки, а CI перезапускает бинарь по нескольку раз в день.

Туда же, в «Настройки», переехало всё, что было за `⋯` над терминалом — размер
шрифта, уведомления, `〰 smooth`, режим клавиатуры, лог ввода, версия и Install.
Переехало, а не продублировалось: два места на один рычаг расходятся. Кнопка `▾`
(спрятать бары) осталась на панели клавиш — это действие на рабочей поверхности,
а не настройка.

Блок «Настройки» закрывается и **свайпом вниз** внутри него — он раскрывается
вверх от строки внизу ящика, так что тянуть его обратно вниз значит то же, что
нажать эту строку. Считается только от верха панели: сама она прокручивается под
тем же пальцем, и отнимать прокрутку у списка кнопок хуже, чем лишний тап.

Открытый или закрытый блок «Настройки» **помнится**: закрытие ящика его
складывает, но ответа за вас не пишет, поэтому он возвращается таким, каким его
оставили — и на следующем открытии ящика, и после перезагрузки страницы.

### Порядок вкладок: держать и перенести

tmux сортирует сессии по имени — единственный порядок, который никто не выбирал.
Полосу читают слева направо десятки раз в день, и та сессия, к которой вы всё
время возвращаетесь, вовсе не та, чьё имя первое по алфавиту.

Жест — то же нажатие, которым вкладка объясняет свой знак: **подержать** — вкладка
поднимается (и под ней появляется та самая табличка), **повести** — ряд
перестраивается, отпустить — порядок сохраняется. Нажатие без движения остаётся
вопросом про знак. Простое перетаскивание не подходит: им полоса прокручивается,
а она шире экрана.

Порядок хранится в самом tmux, опцией на сессии (`@pockterm-order`, рядом с
клеймом кнопки) — поэтому он переживает перезапуски бинаря (CI ставит новый
несколько раз в день), второй телефон видит тот же ряд, а закрытая сессия уносит
своё место с собой. Сессия, начатая после последнего перетаскивания, встаёт в
конец ряда, а не в середину чужой раскладки.

### Полоса вкладок: цвет говорит, что делает сессия

Вкладка отвечает на три разных вопроса и говорит их тремя разными способами:
какие сессии есть — сам ряд, в какой ты сейчас — **рамка**, что каждая делает —
**заливка**:

| Вид | Что значит |
|---|---|
| обычная | наблюдателю сказать нечего: сессия молчит с тех пор, как он смотрит |
| бегущая фиолетовая | на экране появляется вывод прямо сейчас |
| зелёная | затихла после того, как что-то делала (то же событие, из которого рождается уведомление «закончил») |
| бегущая синяя с жёлтым `!` над верхней границей | агент ждёт ответа: на экране меню, и без ответа ничего не произойдёт |

Синее старше остальных и не ждёт истории: меню на экране — единственное
состояние про человека с телефоном, а не про машину, поэтому оно перебивает и
«работает», и «затихла» (иначе вкладка сказала бы «закончил» про агента, который
стоит и спрашивает). Знак нарочно вылезает половиной за границу вкладки. Это то же
распознавание, из которого рисуются кнопки ответа, — только кнопки есть у сессии,
которая на экране, а вопрос обычно в той, которой на экране нет.

Состояние считает не страница, а тот же наблюдатель за панелями, который решает
про уведомления, — поэтому цвет и уведомление не могут разойтись. Оно приезжает
полем `state` в списке сессий и обновляется раз в три секунды, пока терминал на
экране и страница на переднем плане: телефон в кармане держит сокет часами, и
опрашивать tmux ради полосы, которую никто не видит, незачем.

Рамка вместо заливки для активной — потому что заливка занята: раньше «ты здесь»
было заливкой, и тогда вкладка, в которой ты сидишь, оставалась единственной, по
которой нельзя понять, работает ли её агент.

Фиолетовая проходит медленно и в обе стороны, и у каждой вкладки своя фаза (она
выводится из имени сессии, поэтому не сбрасывается при перерисовке ряда): ряд, в
котором всё мигало в такт, читался как одна декорация полосы, а не как несколько
сессий, каждая при своём деле.

Кроме цвета вкладка носит **зелёный геральдический щиток в правом нижнем углу**
(плоский верх, острый низ) — столько шелов
и мониторов, сколько агент держит запущенными. Это второй ответ, а не оттенок
первого: цвет гаснет, как только агент замолчал, а фоновые задачи с ним не
заканчиваются, и «затихла» против «затихла, пока два монитора смотрят» — разные
вещи. В углу, а не после имени: ряд прокручивается вбок, и читают в нём именно
имена. Счётчик снимается со собственной строки
состояния агента (`1 shell, 1 monitor`) и живёт в том же списке сессий полями
`shells` и `monitors`; строка «… still running», которую агент печатает в конце
хода, не считается — она была правдой в тот момент и про «сейчас» не говорит.

## Уведомления

Под наблюдение попадает сессия, к которой хоть раз подключились через
pockterm; она остаётся под ним, пока жива. Сервер раз в две секунды
читает её экран через `capture-pane` и различает два события:

- **просит ответ** — на экране появилось интерактивное меню (одно
  сообщение на меню, не на каждый опрос);
- **закончил** — счётчик агента (`✻ Pondering… (4m 23s · …)`) исчез с экрана и
  не вернулся за 4 с, либо — там, где счётчика нет вовсе, — экран не менялся
  `POCKTERM_IDLE` после того, как что-то происходило.

**Решение одно, каналов два.** Событие уходит в Telegram и тем же кадром
по вебсокету — открытой странице, которая покажет системное уведомление
(в приложении — через мост, в браузере — через Notification API). Раньше
страница решала сама, и это была ошибка: она считала активностью любые
байты из сокета, а tmux перерисовывает строку статуса по часам, так что
отсчёт тишины почти не доходил до конца; проверял его таймер, который
Android в свёрнутом WebView душит до одного срабатывания в минуту.
Приходило непонятно что и непонятно когда. Сервер читает панель
напрямую — без строки статуса и без троттлинга.

**Переключатель один, состояний три** — кнопка «🔔» в «Настройках»: `PWA`
(уведомления только открытой странице), `PWA+TG` (плюс Telegram, когда не
открыто ничего) и `Off` (ни туда, ни туда). Состояние живёт на сервере, а не
в браузере: половина того, чем оно управляет, отправляется с хоста телефону,
у которого страница закрыта, и второй телефон не должен спорить с тем, что
хост делает на самом деле. Оно помнится между перезапусками — бинарь ставит
CI на каждый push в `main`, и режим, живущий в памяти, возвращался бы к
умолчанию несколько раз за рабочий день. Без настроенного бота среднее
состояние из цикла выпадает: обещать Telegram, которого нет, — врать.

**Разрешение у браузера страница просит сама, при первом касании.** Умолчание
на сервере — `PWA+TG`, то есть свежая установка сразу в состоянии «уведомляю»,
и тапать переключатель, который уже говорит нужное, никто не станет: раньше
разрешение спрашивалось только оттуда, и новая установка молчала, ничем этого
не объясняя. Не при загрузке, а при касании — запрос без жеста часть браузеров
отклоняет сразу, а остальные показывают тише и незаметнее. Спрашивается один
раз: закрытый без ответа диалог оставляет то же состояние «не спрашивали», и
страница, которая спрашивает на каждой загрузке, теряет право спрашивать
вообще. Дальше остаётся `🔔` пунктиром — тап по ней и есть повтор.

Пока сессия открыта в pockterm и вкладка на экране, уведомления по ней
молчат: ты и так всё видишь. Свёрнутая PWA держит сокет открытым, но
считается невидимой — сообщение придёт. Если система усыпит и сам сокет,
до страницы кадр не дойдёт; Telegram в этом случае остаётся.

Текст короткий и одинаковый в обоих каналах: заголовок называет сессию
(`✅ claude-1 закончил`), в теле — последняя осмысленная строка панели.
Именно осмысленная: снизу у агентских TUI нарисована рамка ввода и
подсказка про шорткаты, и «последняя непустая строка» — это они.

Включить их — одна команда. Создайте бота у @BotFather, напишите ему любое
сообщение (пока вы этого не сделали, Telegram не сообщает боту ваш ID) и
запустите:

```bash
sudo pockterm tg-setup --write /etc/pockterm/pockterm.env
sudo systemctl restart pockterm
```

Команда спросит токен, сама найдёт ID чата, отправит пробное сообщение и
допишет настройки в env-файл (0600), не трогая остальные строки. Если боту
писали из нескольких чатов, она покажет их списком и попросит выбрать:
`--chat <id>`. Без `--write` она просто напечатает строки — вписать руками.

Ссылку в сообщениях задаёт `--link https://ваш.адрес`.

## Замолчавший сокет

Телефон отдаёт соединение между Wi-Fi и сотами когда захочет, и дальний конец
после этого — чёрная дыра: `readyState` у сокета остаётся OPEN, отправка выглядит
успешной, а не приходит ничего. Выглядело это как зависший экран: сообщение ушло
(на ноутбуке видно, что агент отвечает), а телефон стоит на том же кадре и
догоняет через минуту — это минута, за которую сдаётся TCP.

Страница теперь спрашивает: после 10 с тишины уходит `ping`, и если за 5 с ничего
не пришло, сокет выбрасывается и соединение поднимается заново. Любой входящий
кадр — ответ, поэтому занятую сессию никто не пингует. Пока страница не на
экране, вопрос не задаётся: у фоновой страницы таймеры душат до одного
срабатывания в минуту, и рвать сокет из-за замедленных часов хуже, чем то, что
здесь лечится. Возврат на экран — сам повод спросить.

## Развёртывание

Сам pockterm слушает loopback. TLS и аутентификацию (клиентские
сертификаты или встроенный токен) обеспечивает обратный прокси перед
ним. Пример systemd-юнита — `deploy/pockterm.service.example`.
Прокси обязан пропускать WebSocket-upgrade для `/ws` и отключать
буферизацию. Прокси также обязан сохранять заголовок Host в исходном виде
(nginx: `proxy_set_header Host $host;`) — сервер сверяет `Origin` с `Host`
запроса и отклоняет апгрейд, если прокси его переписывает.

## Обновление: ставится сразу, страница предлагает обновиться

Установка нового бинарника перезапускает юнит, а в нём сидит тот, кто этим
терминалом пользуется. Раньше из-за этого установка ждала, пока страницу
никто не смотрит — и ждала ровно того человека, который и ждал исправления.
Теперь `deploy/pockterm-deploy` ставит сборку сразу: перезапуск стоит одного
переподключения, сессия tmux за ним не затрагивается.

| Файл | Что делает |
|---|---|
| `deploy/pockterm-deploy` | проверяет подпись, ставит, перезапускает, откатывает |
| `deploy/pockterm-deploy.path` | замечает появление сборки |
| `deploy/pockterm-deploy.service` | запускает скрипт |

Одинаковые байты перезапуска не вызывают, а не поднявшийся бинарник
откатывается на предыдущий.

Открытая страница после перезапуска переподключается — и продолжает работать
на прежних ассетах. Сама она этого знать не может: её код и есть старый код.
Поэтому сервер в кадре `config` называет версию страницы, которую отдаёт
(`APP_VERSION` из встроенного `web/js/app.js`), а страница сравнивает со своей
и показывает полосу с кнопкой **Обновить**. Перезагрузка по кнопке, а не сама
собой: в поле ввода может лежать недописанное сообщение. Service worker
работает network-first, поэтому обычной перезагрузки достаточно.

Схема рассчитана на CI, который кладёт подписанный файл в
`/var/lib/pockterm/incoming`; ключ подписи нужен потому, что этот каталог
виден сборочной задаче. Проверить скрипт, ничего не трогая на машине:
`make test-deploy`.

## Модель безопасности

pockterm отдаёт полный терминал любому, кто подключился. Относитесь к
нему как к SSH: не выставляйте наружу без TLS и аутентификации.
Бинарник отказывается слушать не-loopback адрес без токена.

Уведомления отправляют кусок экрана во внешний сервис: строку вопроса и
пункты меню либо последнюю строку вывода. Объём ограничен (не больше
восьми пунктов, строки режутся по 200 символов), но содержимое сессии
всё равно покидает хост. `POCKTERM_TG_PREVIEW=off` оставляет только факт
события и имя сессии. Ссылка в сообщении токена не содержит.
